# راهنمای فارسی اجرا

نام پیشنهادی: `drl-context-poi`

کد روش اصلی و ارزیابی‌های داخلی آماده است: Transformer و GRU، ensemble، بازیابی تدریجی context، Double DQN و DQN، bandit و انتخاب مستقیم زیرمجموعه، baselineهای ساده، ablation، محدودیت بودجه، گزارش نتایج و اندازه‌گیری تأخیر واقعی.

آزمایش‌های اصلی با seedهای 11، 29 و 47 تعریف شده‌اند. آزمایش‌های تکمیلی با seed ثابت 11 اجرا می‌شوند. دادهٔ کامل استفاده می‌شود و فاز پایلوت جداگانه‌ای در برنامه نیست. HPO روی validation بخشی از پروتکل نهایی است. تست‌های مصنوعی صرفاً صحت نرم‌افزار را بررسی می‌کنند.

برای شروع، راهنمای README اصلی را دنبال کنید: نصب، تبدیل دیتاست، انتخاب تنظیمات با validation، ساخت برنامهٔ آزمایش و اجرای workerها. در کگل دو worker روی GPUهای 0 و 1 اجرا کنید. روی 3090 یا L40S فقط یک worker کافی است؛ کد وابسته به نام GPU نیست. حافظهٔ دو T4 به یک حافظهٔ 32 گیگابایتی تبدیل نمی‌شود.

فایل `configs/base.yaml` تنظیمات اولیه است، نه تنظیماتی که برتری تجربی آن ثابت شده باشد. قبل از اجرای نهایی، نسخهٔ انتخاب‌شده با validation را در پوشهٔ `configs/frozen` ذخیره کنید و با `--settings-dir configs/frozen` برنامه بسازید. هزینهٔ sourceها باید ابتدا روی دادهٔ آموزش پروفایل شود؛ هزینه‌های دلخواه برای نتیجهٔ مقاله قابل دفاع نیستند.

نسخهٔ Gowalla معرفی‌شده در مثال، استخراج با مستطیل جغرافیایی اطراف کالیفرنیاست؛ با نسخهٔ دقیق منتشرشدهٔ Gowalla-CA یکسان فرض نشده است. در مقاله تعریف، checksum و آمار همین نسخه را بنویسید یا نسخهٔ مستند دیگری را جایگزین کنید.

بخش مقایسه با GETNext، DCHL و iPCM هنوز به نوشتن adapter و اجرای کد رسمی روی پروتکل یکسان نیاز دارد. ابزار دریافت نسخهٔ ثابت کد رسمی و تبادل داده/پیش‌بینی آماده است، اما این موضوع به معنی بازتولید این baselineها نیست. وضعیت دقیق هر بخش در `docs/coverage.md` آمده است.

برای انتشار، دستورات بخش انتهایی README را اجرا کنید. در این تحویل هیچ ریپوی خارجی ساخته نشده و چیزی روی گیتهاب پوش نشده است. دیتاست، مدل‌های آموزش‌دیده و خروجی‌های حجیم به‌طور پیش‌فرض در git وارد نمی‌شوند.
